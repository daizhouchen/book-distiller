# Deepening Protocol · 加深协议总纲

**v2.2 协议**——本文档是 book-distiller 加深版的宪法补编。所有骨架、脚本、模板、example 都引用本协议条款编号（§N.M）作为对齐锚点。本协议在 v1 核心宪法（`core-thesis.md`）之上增量约束，**不替换、只加强**。

> **v2.2 演进方向**（与 v2.1 比）：从"加密度"转向"排版可读"——加 §10 重点突出与排版规范；§2 长字段引入「结构化分段」可选格式（subhead + paragraphs）；推导链 derivation_chain 强制渲染为视觉列表；关键短语自动加重。**老 distill.json 仍可工作**——render.py 用启发式智能分段处理旧 long string。

> 加深不是堆字。加深是让"事实支撑观点、揭示系统逻辑、事实陈述本身也要系统化"四句话在产物里**真的**兑现到位——而不是停留在 schema 字段名上。
>
> **v2.1 演进方向**（与 v2 比）：从"加维度"转向"加密度"——每模块字数翻倍、原文锚点翻倍、专题字段必填、推导链更详。**不再分档**——所有书统一按巨著档执行；工具书也按这个密度走，被拉长的部分会展现成清单 + 系统对照（而不是被强行注水）。

## §2 · 8 个新字段 · schema 定义

distill.json 在 v1 schema 基础上**增量**以下字段。所有新字段都允许空数组/空对象（不适用则空），但适用性规则（§4）触发时必填。

### §2.1 · `schools_of_interpretation`（学派论争）

```json
"schools_of_interpretation": [
  {
    "school": "学派名（如：脂评派 / 索隐派 / 考据派 / 文本批评派）",
    "core_position": "一句话核心立场（≤40字）",
    "key_figures": ["代表人物1", "代表人物2"],
    "evidence_anchors": [
      {"source": "支持本派立场的关键文献/章节", "summary": "一句话"}
    ],
    "our_judgment": "采纳 | 部分采纳 | 存疑 | 反驳 + 一句话理由"
  }
]
```
- 适用书 ≥ 3 派；深读独占模块。

### §2.2 · `version_variants`（版本/译本差异）

```json
"version_variants": [
  {
    "version_a": "...", "version_b": "...",
    "diff_locus": "...", "diff_content": "...",
    "interpretive_significance": "..."
  }
]
```
- 适用书 ≥ 5 处对照；深读独占模块。

### §2.3 · `author_position_deconstruction`（作者立场解构）

```json
"author_position_deconstruction": {
  "class_position": "≤30字",
  "knowledge_boundary": "≤30字",
  "writing_motive_shadow": "≤30字",
  "evidence": [{"facet": "class | knowledge | motive", "anchor": "...", "elaboration": "..."}]
}
```
- 所有书强制；evidence ≥ 3 条；渲染为独立模块。

### §2.4 · `chapter_level_notes`（章节级覆盖）

```json
"chapter_level_notes": [
  {
    "chapter": "第N回 / 第N章",
    "anchor_event": "...",
    "interpretation": "≥600 字",
    "cross_link": "..."
  }
]
```
- 长书（>30 万字）≥12 回（**v2.1 提升**）；中等长书 ≥8 回；短书可降级为"主题级覆盖" ≥8 个主题；深读独占模块。
- **每条 interpretation ≥600 字**（v2.1 新增）—— 章节级是巨著之所以厚的核心承载。

### §2.5 · `thought_coordinates`（强化版思想坐标）

```json
"thought_coordinates": {
  "同题延伸": [
    {"referenced_work": "...", "referenced_author": "...", "position": "...", "relation_to_book": "..."}
  ],
  "对立视角": [...],
  "承继关系": [...],
  "现代回响": [...]
}
```
- 四维各 ≥4 条（**v2.1 提升**）。

### §2.6 · `scene_dissections`（场景细读）⭐ v2.1 新增

```json
"scene_dissections": [
  {
    "scene_title": "场景标题",
    "scene_locus": "第N回/第N章 · 一句话定位",
    "original_text_excerpt": "≥300 字的关键原文段落",
    "dissection_layers": {
      "blocking": "调度（人物站位、空间布局、入退场顺序）",
      "language": "语言层（用词、句式、对白节奏、潜台词）",
      "sensorium": "感官层（视觉/听觉/触觉/嗅觉细节）",
      "subtext": "潜文本（没说出来的、被遮蔽的、暗示的）",
      "structural_function": "在全书中的结构功能（前后呼应、母题承担）"
    },
    "key_close_reads": [
      {"phrase": "原文中的关键短语", "reading": "为什么这个细节关键 ≥80 字"}
    ],
    "echoes": "本场景与全书其它场景的呼应（≥3 处）"
  }
]
```
- **数量要求**：小说/叙事类书 ≥5 个；论证书可空但建议 ≥2 个例证场景；工具书可空。
- **位置要求**：独立模块，渲染为深读独占；每条 ≥1000 字。
- 这是 v2.1 最重要的新字段——把"对书内容写厚"从抽象目标落到具体可量化的产出。

### §2.7 · `character_dossiers`（人物小传）⭐ v2.1 新增

```json
"character_dossiers": [
  {
    "name": "人物名",
    "tier": "primary | secondary | minor_but_pivotal",
    "appearance_arc": "在书中的出场轨迹（≥150 字）",
    "core_paradox": "人物的核心矛盾（一句话 ≤30 字）",
    "key_scenes": [
      {"scene": "关键场景定位", "what_it_reveals": "暴露了人物的什么 ≥60 字"}
    ],
    "language_signature": "人物的语言印记（说话方式、用词偏好）≥80 字",
    "fate_pattern": "命运模式（≥150 字）",
    "reading_through_lens": "从我们的母题视角看这个人物 ≥150 字"
  }
]
```
- **数量要求**：人物为主的书（小说、传记、史书）≥5 人（巨著 ≥10 人）；论证书/工具书可空。
- **位置要求**：独立模块；每条 ≥600 字；深读独占。

### §2.8 · `poetics_dossiers`（诗词曲赋专题）⭐ v2.1 新增

```json
"poetics_dossiers": [
  {
    "title": "篇名（如：葬花词 / 姽婳词 / 咏螃蟹）",
    "locus": "第N回",
    "speaker_or_voice": "由谁所作 / 叙事声音",
    "full_or_excerpt": "全文 或 关键节选（≥150 字）",
    "form_analysis": "形式分析（体裁、韵律、典故运用）≥150 字",
    "content_analysis": "内容分析（在情节/人物中的功能）≥200 字",
    "intertextual_anchors": [
      {"refers_to": "化用了什么前文学", "significance": "意义"}
    ],
    "fate_foreshadowing": "诗词中的命运预告（如有）≥80 字"
  }
]
```
- **数量要求**：含诗词曲赋的书（古典小说、思想史经典、诗集、词集、戏剧）≥3 篇；现代书无诗词可空。
- **位置要求**：独立模块；每条 ≥600 字；深读独占。

## §3 · 推导链显式化 + 单 quote 长度（§1.14 / §1.4b 细则）

### 推导链
每个 module 的 `viewpoint_layer.core_claim` 必须配 `derivation_chain` 字段，包含 **≥4 步**（v2.1 提升）：

```json
"viewpoint_layer": {
  "core_claim": "核心观点一句话",
  "derivation_chain": [
    {"step": 1, "type": "fact", "content": "..."},
    {"step": 2, "type": "mechanism", "content": "..."},
    {"step": 3, "type": "analogy | counterfact | synthesis", "content": "..."},
    {"step": 4, "type": "claim", "content": "..."}
  ],
  "modern_transfer": "...",
  "caveats": "..."
}
```
不允许"事实跳到结论"——每步必须有上一步作为支撑。

### Quote 单条长度
每条 `quote_pairs[i].original` 必须 ≥100 字（**v2.1 新增 §1.4b**）。锚点不是关键字搜索结果，是**让读者能看到上下文的小段落**。场景类锚点（出现在 scene_dissections.original_text_excerpt 之外的）巨著建议 ≥150 字。

每条 `quote_pairs[i].analysis` 必须 ≥80 字——解读不能只是"翻译一遍"，要给出 mechanism 层面的解释。

## §4 · 适用性判定规则

### §4.1 · 学派论争（§2.1）
**强制清单**：中国古典（红楼/金瓶/水浒/三国/西游/金刚经/道德经/论语/庄子/史记/诗经）；西方经典（圣经/伊利亚特/神曲/莎士比亚/堂吉诃德/源氏物语/追忆似水年华）；思想史经典（康德三大批判/纯粹理性批判/资本论/尼采全集/存在与时间）；任何写于 1900 年前且仍在被解读争论的书。
**不适用**：工具书、单一作者立场鲜明的论证书。

### §4.2 · 版本差异（§2.2）
**强制**：古籍多版本/钞本（红楼/金瓶/史记/道德经/莎士比亚原稿）；重要译本之争（佛经汉译/圣经版本/追忆似水年华/源氏物语）；同一作者修订版差异（尼采《查拉图斯特拉如是说》前后版本）。

### §4.3 · 章节级覆盖（§2.4）
**强制**：原书 > 30 万字（150 页+ 中文 / 250 页+ 英文）。降级方案：中等长度书用"主题级覆盖" ≥ 8 个主题。豁免：散文/格言/诗集（用"代表篇章选粹" ≥ 5 篇）。

### §4.4 · 场景细读（§2.6）⭐ v2.1 新增
**强制清单**（≥5 个场景）：
- 所有小说（古典/现代/类型小说）
- 戏剧（莎士比亚/曹禺/契诃夫等）
- 史书（史记/资治通鉴/三国志——选关键事件场景）
- 报告文学/纪实文学
- 任何含具体场景叙事的书

**降级**（≥2 个例证场景）：思想史经典（如康德举的咖啡馆例子、尼采的"市场之蝇"等情境化论证）；社科著作（如《乡土中国》《菊与刀》的具体田野场景）。

**可空**：纯抽象论证（数学、逻辑学）；纯模型工具书（如《非暴力沟通》——可用"实操剧本"代替）。

### §4.5 · 人物小传（§2.7）⭐ v2.1 新增
**强制清单**（≥5 人，巨著 ≥10 人）：
- 所有小说类（人物为核心承载）
- 传记/回忆录
- 史书（必有关键人物专题）
- 群像类作品（《世说新语》《史记·列传》等）

**降级**（≥3 个核心思想家小传）：思想史著作可写"承载思想的关键人物"。

**可空**：模型工具书、纯抽象论证、纯诗集。

### §4.6 · 诗词专题（§2.8）⭐ v2.1 新增
**强制清单**（≥3 篇）：
- 古典小说（红楼/金瓶/水浒/西游/儒林外史——含大量诗词）
- 戏剧（牡丹亭/桃花扇/长生殿等）
- 诗集/词集/曲集（必有专题）
- 思想散文（庄子/老子的诗化论证）
- 任何文体里有诗词曲赋承担叙事/抒情功能的书

**可空**：纯论证书、纯工具书、现代纯叙事小说（无诗词）。

## §6 · 9 步流程在 v2.1 的位置变化

| 步骤 | v2.1 增量 |
|------|--------|
| 步骤 1 母题识别 | 不变 |
| 步骤 2 基因检测 | 加：判断 §4.1-§4.6 6 条适用性，输出 applicability_map |

## §7 · 失败模式与回流

| 现象 | 回流到 | 原因 |
|------|--------|------|
| quality_check 红：单模块 < 4500 字 | 步骤 7 | 写作密度不够，推导/原文锚点没充实 |
| quality_check 红：单 quote < 100 字 | 步骤 4-7 | 锚点采集太碎，没拿完整段落 |
| quality_check 红：scene_dissections < 5（小说类） | 步骤 4-6 | 场景级扫描没做或没填进 schema |
| quality_check 红：character_dossiers < 5（人物书） | 步骤 5-6 | 人物聚合没做 |
| quality_check 红：poetics_dossiers < 3（含诗词书） | 步骤 4-7 | 诗词专题没立章 |
| quality_check 红：思想坐标某维 < 4 | 步骤 3-6 | 信源采集没拉够外延 |
| quality_check 红：学派 < 3（适用书） | 步骤 3 | 信源采集没主动找学派代表作 |

## §10 · 重点突出与排版规范（v2.2 新增）

加深之后的第二个台阶是排版——厚的内容如果连段都没分、重点都没标，读者眼睛要爆炸。本章定义所有长字段的分段、重点、视觉层级规范。

### §10.1 · 长字段的三种格式（向后兼容）

凡 ≥600 字的字段（systematized_facts / cross_dim_weaving / modern_transfer / caveats / scene_dissections.dissection_layers.* 等）支持三种格式，render.py 都能渲染：

**格式 A · 纯字符串**（v2.0/v2.1 兼容，render.py 走启发式智能分段）：
```json
"systematized_facts": "贾宝玉这一人物形象……第一组事实，是宝玉对科举的拒斥……第二组事实，是宝玉对女儿世界的特殊投入……"
```
启发式按以下顺序切段：① 显式 `\n\n` ② 「第N组事实/第N层/第N组」开头 ③ 「其一/其二/其三」开头 ④ ≥600 字按句号累计 350 字成段。

**格式 B · paragraphs 数组**（v2.2 推荐——LLM 写作时直接显式分段）：
```json
"systematized_facts": {
  "paragraphs": [
    "贾宝玉这一人物形象……（开篇总述）",
    "第一组事实，是宝玉对科举的拒斥……",
    "第二组事实，是宝玉对女儿世界的特殊投入……",
    "……总钥匙——他拒绝任何形式的人格分等。"
  ]
}
```
每段独立 `<p>` 渲染，自带首行缩进 + 段间距。

**格式 C · subhead+body 结构化**（v2.2 推荐巨著用）：
```json
"systematized_facts": [
  {"subhead": "宝玉对科举的拒斥", "body": ["第三回……", "第九回……", "宝玉对科举不是消极抵触……"]},
  {"subhead": "宝玉对女儿的投入", "body": ["第二回……", "第十九回……"]},
  {"subhead": "情不情行为", "body": "..."}
]
```
渲染为 `<h6 class="layer-subhead">小标题</h6>` + 段落组，视觉层级最强。

### §10.2 · 推导链强制渲染（§3 升级）

`derivation_chain` v2.2 起强制渲染为视觉编号列表（不能只是字符串）。每步 schema：

```json
{"step": 1, "type": "fact|mechanism|analogy|counterfact|synthesis|claim|refutation", "content": "..."}
```

render.py 渲染为带编号圆点 + 类型标签 + 正文的 `<ol class="derivation-chain">` 列表，是 viewpoint 层视觉重心。

### §10.3 · 关键短语自动加重

render.py 自动识别并 `<strong class="kw">` 加重以下三类短语：
- **元论述标记词**：总钥匙 / 总宣告 / 临界点 / 拐点 / 反证 / 反讽 / 核心命题 / 内在悖论 / 结构性宿命 等
- **「」内的关键短语**：长度 2-12 字的引号内容，自动加重（典型如「情不情」「混账话」「冷月葬花魂」）
- **段首小标题**：「第N组事实，」「第N层，」「其N，」自动识别为 `.para-subhead` 或 `.para-qiyi`

写作时无需显式标记——只要在文本里使用上述结构（用「」标关键短语、用「第N组事实/其一」分段），render.py 自动处理。

### §10.4 · 排版硬下限（v2.2 新增）

为保证可读性，长字段必须满足：

| 条款 | 指标 | v2.2 硬下限 |
|------|------|-----------|
| §10.4.1 | 单字段 ≥600 字 | 必须 ≥3 个段落（用格式 B/C 或文本里 ≥3 个段落标记） |
| §10.4.2 | 单字段 ≥1500 字 | 必须 ≥4 个段落 |
| §10.4.3 | 单字段 ≥3000 字 | 必须 ≥5 个段落（人物/场景重模块的 systematized_facts） |
| §10.4.4 | 推导链 derivation_chain | 必须填且 ≥4 步（§3 不变） |
| §10.4.5 | 关键短语 / 「」短语 | 单模块至少 ≥5 处（场景/人物模块 ≥10 处）确保 .kw 高亮密度 |

quality_check.py 检查：长字段段落数 < 阈值时给 `[v2.2 排版警告]`。

### §10.5 · CSS 视觉层级（template.html 已实现）

排版的视觉效果由 template.html 的 CSS 实现：
- `.para-subhead` 朱砂色 + 左竖线 + 浅红底
- `.para-qiyi` 松石色加粗
- `.kw` 朱砂细加重 + 虚下划线
- `.layer-subhead` 灰墨小标题 + 底边线，三层各自配对色
- `.view-claim` 朱砂大边框 + 浅红底（核心判断单独 callout）
- `.view-caveat` 松石色边框 + 浅蓝底（边界单独 callout）
- `.derivation-chain` 编号圆点（朱砂） + 类型标签（淡金） + 正文 grid 布局
- `.layer p` 首行缩进 2em + 行高 1.95（中文长段标准排版）

不要在 distill.json 里直接写 HTML 标签——所有视觉层级由 render.py 按 schema 识别 + template.html CSS 提供。
